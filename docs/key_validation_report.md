# Database Design Decisions

### customers
- customer_id is the natural primary key.
- customer_unique_id is a business identifier.

### orders
- order_id is the primary key.
- customer_id is treated as a foreign key even though it is unique in this dataset because business relationships take precedence over uniqueness.

### order_items
- Uses a composite primary key (order_id, order_item_id).

### order_payments
- Uses a composite primary key (order_id, payment_sequential).

### order_reviews
- review_id alone is not unique.
- Composite key (review_id, order_id) is required.

### geolocation
- No natural primary key exists.
- The raw table is preserved exactly as provided.
- Deduplication will occur later in the dbt transformation layer.

### category_translation
- Lookup table for translating Portuguese product categories into English.
